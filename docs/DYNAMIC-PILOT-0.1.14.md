# 0.1.14-rc.1：五英雄布局与动态动作扩围

适用Steam Build 26880829，可从已知0.1.6～0.1.13组合升级。保留已安装词典、字体及通用配置。

## 两份0.1.13日志的结论

`115132-3d0cd9`和`115959-a2cf79`均加载了正确的0.1.13 DLL与动态配置；未发现审计所检查的采集、字体或渲染异常。两种Construct按钮、异能阶段次数、发现标题有实际动态命中。最低生命值选择和组合异能提示未在两份新日志中出现，继续待验证。日志命中不代替画面或点击验收。

新日志进入五英雄布局，暴露了三英雄路径之外的“在此打出”“打出一张牌”等遗漏；本轮扩展对应用途识别，同时校验3人布局位置1～2、5人布局位置1～4的有效组合。四英雄布局尚无实机路径证据，保留待观察。

## 本轮新增

- 五英雄布局下角色选择、放置按钮及相关已有牌库选择规则的路径识别；角色／卡牌身份保护不变。
- 破坏确认按钮的数量格式，包括日志中的0～7张牌；严格区分牌数和目标数。
- 破坏至多N个目标／至多N张在场卡牌的完整提示。
- 进行出牌阶段、选择立即进行出牌阶段的英雄，以及跳过失能阶段。
- 独立展示窗口标题、召唤结果标题；展示窗口要求动作来源与标题来源一致。
- 准备及各阶段普通标题的显示兜底，继续保留原游戏计数。
- 生命值降至指定数值的结算消息、击败反派的胜利提示。仅修改消息文字，不修改生命值。
- 新游戏、随机选择、返回、分享、消息确认的已观察按钮。

卡组名称、Construct关键词和异能／失能能力正文继续按既定卡组审核范围处理。

## 安装与复测

1. 关闭游戏后运行 `01-Install-Dynamic-Pilot.cmd`，可直接覆盖升级0.1.13。
2. 五英雄局面中检查非当前英雄的“在此打出”“打出一张牌”，确认仍可正常操作。
3. 选择破坏卡牌时观察确认按钮数字变化，确认“至多”与对象范围显示正确。
4. 自然遇到展示窗口、召唤或游戏结束时检查标题与提示；生命值更新和读档／回菜单继续随游玩观察。
5. 遇到问题保留完整截图并运行 `02-Collect-Evidence.cmd`。采集可在游戏运行时执行。

`03-Restore-Previous.cmd`恢复安装前DLL和独立配置；从0.1.13升级则恢复0.1.13。

## 审计改进与验证边界

审计现在只在同一控件上存在完整原文、且当前规则能产生完全相同输出时，识别“英文卡名＋中文标题”为已翻译输出；不能仅凭中文后缀认定完成。已观察的纯数字富文本按精确样式识别为非翻译目标；包含文字的变体仍须审查。这两项只影响离线审计，不扩大游戏数字处理范围。

累计328个观察项：145项当前可转换，12项中文，17项可追溯的已翻译输出，64项纯数字、25项带样式数字，65项仍未匹配。剩余65项逐项登记为50项卡组专名／正文、11项固定界面、4项符号；不能将其等同于全游戏剩余量。

本轮新增38个实际位置／原文组合的精确译文、富文本、幂等回归。Release编译、102项脚本测试、835项运行时检查、147个上下文契约和13个分类契约通过。新增显示待Windows实机验收；第一阶段仍未结项。

不调用TMP.text getter，不修改模型、伤害、抽牌或计数逻辑。已确认为原生问题的抽牌次数不递减不重复处理。
