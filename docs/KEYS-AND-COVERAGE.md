# 稳定键与覆盖边界

## 键名不是原文，也不是每次重新计算的数组位置

界面样板采用持久编号（如 `ui.label.0001`）；卡文采用 `card.LegacyCharacter.body.001`。这些编号本次首次分配后固定保存在 registry 中，不随文件排序、英文标点或译文改变重新编号。

`kind + locator + original` 是当前 0.1.4 运行匹配条件，`key` 是协作身份，`sourceSha256` 是原文版本指纹。三者分开维护。

后续有可靠的游戏原生字段 ID 时，新增条目优先使用该 ID；不要批量重命名现有键。将来拆分一条/合并多条文本时，显式登记新旧关系并逐条审查，不靠模糊匹配自动继承译文。

同样的英文位于不同控件或卡牌，保留不同的稳定键。当前运行层同一个控件名下的相同原文无法再区分父级场景；不能创建两个不同译文假装支持这种区分。遇到此类需求，应先扩展运行定位，再更新 schema。

## 源文变更

- 新增：分配新键，登记实际定位来源，空译文开始。
- 改词：保持原键，更新 original 与 sourceSha256；旧快照因原文不符而阻止构建，完成平台源文同步与译文复核后再继续。
- 删除：先用 diff 明确列出；快照中的未知旧键会阻止构建，避免悄悄遗留。
- 翻译修改：只改变 translation，不改键、原文或运行定位。

```sh
python3 tools/catalog.py diff old-registry.json baseline/registry.json
```

registry 是维护者控制的版本化清单；sourceSha256 用于侦测源文版本差异，不是授权签名。

## 当前覆盖

| 类别 | 协作格式 | 0.1.4 运行支持 | 当前样板 |
|---|---|---|---|
| 菜单/按钮标签 | ui.label | 控件名+原文精确匹配 | 37 项 |
| 卡牌正文 | card.body | 卡 ID+整行原文；保留动态规则保护 | 52 条，27 个基础卡牌 ID；新增部分待实机验收 |
| 卡名、关键词类型、副标题 | 后续登记 | 本轮未扩展和验收 | 0 |
| 阶段名与模板输出 | 后续登记 | 原占位符交回游戏解析 | 0 |
| 风味文本、漫画出处、角色介绍 | 后续登记 | 本轮未扩展和验收 | 0 |
| 烘焙在图片中的文字 | 图片资产映射，另行设计 | 文本 JSON 不能直接替换 | 0 |
| 生命值、计数器、动态数字 | 不进入此翻译词典 | 保留游戏原处理 | 不适用 |

正文按牌组存入 `Legacy.json`（27 条）与 `BaronBlade.json`（25 条），覆盖基础牌的普通、失能/翻面、进阶与设置文本。变体和事件另批处理。`file` 仅控制协作分组，不改变稳定键或运行定位。来源路径与完整原文见 `baseline/batch01-source-index.json`。

样板已具备中文显示，不等于全部语义完成审核；不据此冻结角色译名。ParaTranz 术语表应在取得项目最新审定总表后独立导入，避免混用旧稿。

## 发布分层

运行支持版本保持 0.1.4；协作工具链版本为 0.1.2。未来文本包采用独立版本，并记录所需运行版本及游戏构建。仅改译文不重编译 DLL；新增未支持文本类别需要单独安排运行适配和回归测试。
